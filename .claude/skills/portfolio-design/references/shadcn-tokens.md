# shadcn Tokens — Indigo Mapping Recipe

How the primary color is wired into shadcn/ui for this project. **This is a recipe applied once at site setup, in `globals.css`.** Until the Vite + shadcn project exists there is nothing to edit yet — this documents *what to do when it does*.

## ⚠️ Verify with Context7 before applying

The shadcn theming format changes between versions (it moved from HSL under Tailwind v3 to **OKLCH under Tailwind v4**, mapped via `@theme inline`). **Query the Context7 MCP for the current shadcn theming docs before writing `globals.css`** — confirm the token names, the color format, and whether `@theme inline` is still the mechanism. Treat the values below as the intended *design*, and let Context7 confirm the exact *syntax* for the installed version.

## The strategy (approach A)

shadcn components consume **semantic** tokens (`--primary`, `--ring`, `--primary-foreground`). We point those at **Tailwind's `indigo` scale** (the primitive values). Components never hardcode `bg-indigo-600` — they use `bg-primary`, so the site themes from one place and dark mode works. This is the primitive→semantic pattern.

## Indigo scale (Tailwind) → reference values

Tailwind `indigo`, with OKLCH equivalents for the tokens that matter. Confirm exact OKLCH via Context7/Tailwind docs for the installed version; these are close targets.

| Tailwind | Hex | OKLCH (approx) | Role |
|---|---|---|---|
| indigo-500 | #6366F1 | oklch(0.585 0.204 277) | ring / hover accents |
| **indigo-600** | **#4F46E5** | **oklch(0.511 0.226 277)** | **--primary (light mode)** |
| indigo-400 | #818CF8 | oklch(0.673 0.170 277) | --primary (dark mode, lighter for contrast) |
| white | #FFFFFF | oklch(1 0 0) | --primary-foreground (text on indigo) |

## Token mapping (light + dark)

Only the tokens we override for the indigo brand are shown — leave the rest of shadcn's neutral scale as generated by `shadcn init`, unless Marcel wants a warmer/cooler neutral.

```css
/* globals.css — indigo overrides. Confirm format/mechanism via Context7. */
:root {
  --primary: oklch(0.511 0.226 277);            /* indigo-600 */
  --primary-foreground: oklch(1 0 0);           /* white */
  --ring: oklch(0.585 0.204 277);               /* indigo-500 */
}

.dark {
  --primary: oklch(0.673 0.170 277);            /* indigo-400 — lighter so it reads on dark bg */
  --primary-foreground: oklch(0.205 0 0);       /* near-black text on the lighter indigo */
  --ring: oklch(0.585 0.204 277);
}
```

Under Tailwind v4, these `--primary` etc. are bound to `bg-primary`/`text-primary` via the `@theme inline` block that `shadcn init` generates — don't remove that block.

## Why indigo-400 in dark mode

indigo-600 on a near-black background is too low-contrast for accessible text/focus. Stepping the primary lighter (indigo-400) in dark mode keeps contrast healthy. Marcel audits accessibility professionally — verify the final contrast (WCAG AA) once the theme is live.

## Do / don't

- ✅ `className="bg-primary text-primary-foreground"`
- ✅ Adjust the palette by editing these few token lines — everything follows.
- ❌ `className="bg-indigo-600"` on components (breaks theming + dark mode).
- ❌ Copy an OKLCH value from memory without confirming the format for the installed shadcn/Tailwind version via Context7.
