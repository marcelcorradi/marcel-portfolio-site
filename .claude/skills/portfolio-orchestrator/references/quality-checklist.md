# Quality Checklist

Run this before presenting any page or case study as "done". Derived from the IxDF "Build a Standout Portfolio" course (the 7 common mistakes) and what design leaders look for. The goal is to catch the predictable reasons portfolios get rejected — systematically, every time.

For each item, either confirm it passes or flag it. If it fails, fix it or route it back to the right specialist skill before calling the work done. It's fine to present with a known gap *as long as you name the gap explicitly* (e.g. "cover image is a placeholder", "results metric still needed from Marcel").

## Content quality

- [ ] **Curation / role alignment** — Does this project belong in a Product Designer / Design Systems portfolio? Is it one of Marcel's best, or does it dilute? (Quality over quantity — a weak case drags down the perceived level of all the others.)
- [ ] **Leads with results (inverted pyramid)** — Does the case/home open with the outcome and hook, not a slow chronological build-up?
- [ ] **Quantified results** — Are concrete metrics present where they exist (tokens, components/variants, adoption, WCAG %, devs)? Recruiters look for evidence of real impact.
- [ ] **Self-reflection** — Does the case show learnings / what he'd do differently, not just a task list ("I did X, then Y")? This demonstrates critical thinking.
- [ ] **Differentiator visible** — Does the design-systems + CS + builds-with-AI angle come through where relevant?
- [ ] **No inventing** — Every claim traces to real facts (CV / Marcel's input). No fabricated metrics or projects.

## Craft / carefulness

- [ ] **No typos or grammar errors** — The portfolio itself is a work sample; carelessness reads as poor design attention.
- [ ] **Visual consistency** — Consistent typography, spacing, and UI treatment across the page and between sections.
- [ ] **Personalization** — Doesn't look like an unmodified popular template. Has intentional, specific choices (the "signature").

## Web standards (this is a website, so these are non-negotiable)

- [ ] **Responsive** — Works down to mobile; body never scrolls horizontally.
- [ ] **Accessible** — Sufficient color contrast, visible keyboard focus, semantic structure, reduced-motion respected. (Marcel specializes in accessibility audits — the site must practice what he preaches.)
- [ ] **Navigation clarity** — A visitor can find cases and contact without hunting. No dead ends.

## Home-specific

- [ ] **Hook in the first screen** — Name, what he does, and why he's worth reading, above the fold.
- [ ] **Featured work is scannable** — Cards with meaningful titles, short descriptions, skill + attribute tags (e.g. fintech, e-commerce), whole card clickable with hover feedback.
- [ ] **Contact present** — Email / LinkedIn / GitHub reachable.

## Case-specific

- [ ] **Reads like an article** — Single column, clean, focused on readability (Medium-like), not a cluttered dashboard.
- [ ] **Visual context** — Shows the work in context, before/after where it helps, clean final UI.
- [ ] **Clear scope up front** — Project type, Marcel's role, timeframe, tools.
