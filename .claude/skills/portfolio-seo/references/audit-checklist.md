# SEO audit checklist

Adapted for this site from `coreyhaines31/marketingskills` (seo-audit, ai-seo, schema) and
`addyosmani/web-quality-skills` (seo). The international, e-commerce, local and
programmatic sections are left out: this is a single-language personal site of about a
dozen pages.

Every item needs **evidence**: the command, tool output or observation. "Looks fine" is
not evidence. If an item can't be checked from here (Search Console data, for example),
mark it *not verified* and say what is needed.

## 0. Gather first

```bash
npm run build                                   # prints route shells + sitemap counts
ls dist dist/cases                              # what actually ships
cmp dist/index.html dist/cases/<slug>.html      # identical = trap 1 is still open
curl -s -o /dev/null -w "%{http_code}\n" https://marcelcorradi.com/<path>
curl -s -A GPTBot https://marcelcorradi.com/<path> | grep -oE '<title>[^<]*</title>|canonical" href="[^"]*"'
npx -y lighthouse@12 <url> --only-categories=performance,seo --form-factor=mobile \
  --output=json --output-path=<scratchpad>/lh.json --chrome-flags="--headless=new" --quiet
```

The PageSpeed Insights API rate-limits without a key. Lighthouse locally works (a
`chrome-launcher` error on exit is harmless, the JSON is written).

Ask Marcel for a Search Console export (Performance → Queries and Pages, last 3 months)
when the audit is about what ranks. Nothing else here can see Google's side.

## 1. Crawl and index

| Check | How | This site's known state |
|---|---|---|
| Every real route answers 200 | `curl -w "%{http_code}"` | Route shells handle it. Trailing-slash URLs (`/cases/x/`) 404, which is acceptable as long as nothing links to them |
| Unknown URLs answer a real 404 | `curl` a made-up path | `public/404.html` answers 404 with `noindex` |
| `robots.txt` allows crawling and names the sitemap | read it live | `Allow: /` for `*`, sitemap listed |
| AI search bots aren't blocked | `robots.txt` has no `Disallow` for GPTBot, ChatGPT-User, PerplexityBot, ClaudeBot, Google-Extended, Bingbot | Allowed via `*` |
| Sitemap lists exactly the indexable URLs | compare `sitemap.xml` to routes minus noindexed | Generated by `build-sitemap.mjs` |
| **Raw HTML canonical is self-referencing** | `grep canonical` in each `dist` shell | **Trap 1**: all point at `/` |
| No conflicting robots directives | `noindex` only on stub, NotFound, 404 | See SKILL.md trap 3 |
| Indexed at all | Search Console → Pages. `site:` search is a weak proxy | Not verifiable without GSC |

## 2. What a crawler receives

| Check | How |
|---|---|
| Raw HTML has the page's own title, description, canonical, OG | `curl` + `grep`, per route |
| Raw HTML has the page's main content (not an empty root) | `curl ... \| grep -c "<p"` |
| Rendered content matches static content (no cloaking) | compare after any prerender change |
| Share card works | LinkedIn Post Inspector. `og:image` absolute, raster, 1200×630 |

## 3. On-page, per URL

For every URL in `query-map.md`:

- `<title>`: unique, ~60 chars or less, query terms first, `· Marcel Corradi` suffix, **no `—`/`–`**.
- Meta description: unique, 140 to 160 chars, says what the page proves.
- Exactly one H1. The client or tool name and the topic appear in the header or first paragraph.
- Headings are in order (H1 → H2 → H3), no skipped levels.
- Internal links: reachable from the Home. Related cases link to each other. Tool cases
  link to the live listing via `src/content/tools.ts`.
- Images: meaningful `alt`, and sizes that fit their slot (Lighthouse `uses-responsive-images`).
- No keyword stuffing. It also measurably lowers AI citation (Princeton GEO study, −10%).

## 4. Content quality and E-E-A-T

Google's AI features and core ranking use the same signals. What counts here:

- **Experience**: the case shows Marcel did the work (role, timeframe, artefacts, real numbers).
- **Expertise**: specific, technical detail (token counts, architecture, trade-offs), not generic DS talk.
- **Authority**: named clients, published tools, links from the listings and profiles back to the site.
- **Trust**: real contact info, dates on cases, accurate claims. Every number checked against its source.
- **Extractable passages**: the case's key claims work as standalone sentences, because
  AI engines quote passages, not pages. Don't chop the prose into AI bait: Google says
  explicitly not to write separate content for AI.

## 5. Performance and mobile (Core Web Vitals)

Targets: LCP < 2.5 s, INP < 200 ms, CLS < 0.1, measured on mobile.

- Baseline 2026-09-25, Whirlpool case, mobile Lighthouse: performance 92, LCP 2.4 s,
  FCP 2.3 s, TBT 200 ms, CLS 0. Opportunities: responsive images (438 KiB), unused JS (93 KiB).
- The JS ships as one ~700 KB chunk (~220 KB gzip). Vite warns about it on every build.
  Route-level code splitting would cut what a case page loads.
- Mobile: viewport meta present. Tap targets ≥ 48 px, and no horizontal scroll (the
  `portfolio-design` checklist already enforces both).

## 6. Structured data

See `structured-data.md`. Check that it's in the raw HTML (not only injected by JS),
parses in the Rich Results Test, and describes only what's visible.

## 7. Off-site

Not on the site, but part of the same job:

- Profiles that link to marcelcorradi.com: LinkedIn, GitHub, Medium, Upwork, Contra, Dribbble.
  GitHub is checkable from here (no `gh` CLI on this machine, the public API works):
  `curl -s https://api.github.com/users/marcelcorradi | grep '"blog"'` and
  `curl -s https://api.github.com/repos/marcelcorradi/<repo> | grep '"homepage"'`.
  On 2026-09-25 all three were empty.
- Listings that link back: Chrome Web Store (Design Audit), Figma Community (Spec Forge),
  GitHub (Portfolio Kit), atomicolors.com, radardoscoop.com.
- Marketplace presence where hiring searches land (Contra has `hire/design-systems-designers`).

## Report format

`content-drafts/seo-audit.md`:

```
# SEO audit, <date>
## Summary        (3 to 5 lines: state of the site, the one thing that matters most)
## Critical       (breaks indexing or sends a wrong signal)
## High           (costs ranking or clicks)
## Medium         (worth doing, not urgent)
## Measured OK    (checked and fine, with the evidence, so it isn't re-audited)
## Not verified   (what needs Search Console or Marcel)
```

Each finding: **what** · **evidence** · **fix** · **owner skill** · **effort** (S/M/L).
